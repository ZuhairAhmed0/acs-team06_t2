# وين الوقود؟ — Frontend

واجهة React + Vite + Tailwind CSS + daisyUI لتطبيق إدارة رصيد الوقود.

## التشغيل

```bash
npm install
cp .env.example .env
npm run dev
```

اضبط `VITE_API_BASE_URL` على عنوان خادم الـAPI، مثلاً `http://localhost:3000/api/v1`.

## المصادقة والجلسات

المصادقة في هذه الواجهة تعتمد على Session Cookie يصدرها الخادم. جميع طلبات Axios تستخدم `withCredentials: true`. لا تخزّن الواجهة Session ID أو Access Token في `localStorage` أو `sessionStorage`.

يلزم أن يضبط الخادم:
- Cookie من نوع `HttpOnly` و`Secure` في الإنتاج، مع `SameSite` مناسب لطريقة النشر.
- CORS مع `credentials: true` وتحديد Origin الخاص بالواجهة بدلاً من `*`.
- مسارات `POST /auth/login` و`POST /auth/logout` و`GET /users/me` لإدارة الجلسة.
- حماية CSRF للطلبات التي تغيّر البيانات إذا كان إعداد النشر يتطلب ذلك.

## المسارات المستخدمة

تُستخدم المسارات الموجودة في `src/lib/endpoints.js` كما هي، من دون إعادة تسمية أو إضافة مسارات API. النماذج الحالية تفترض أسماء حقول شائعة في جسم الطلب مثل `amount`, `station_id`, `bank_reference` و`fuel_type`. يجب أن تتطابق هذه الأسماء مع DTOs الفعلية في الخادم.

## أدوار الواجهة

- USER: المحفظة، الشحن، المحطات، التخصيص، التحويل، مشتريات الوقود، المعاملات والحسابات البنكية.
- OWNER: ملخص المحطة، المالية، حد التسوية وأسعار الوقود، بناءً على عضوية محطة بدور `OWNER`.
- ATTENDANT: قائمة مشتريات المحطة وتأكيد الصرف، بناءً على عضوية محطة بدور `ATTENDANT`.
- ADMIN: مراجعة الشحن والتسويات.

هذه الحماية لتحسين تجربة الاستخدام فقط؛ يجب أن يفرض الخادم الصلاحيات والتحقق من ملكية الموارد.

## حدود عقد الـAPI الحالي

لم تتم إضافة استدعاءات لمسارات غير موجودة في القائمة الحالية. لذلك تظهر السحب البنكي وفك التخصيص كعمليات غير متاحة إلى أن يضاف لهما endpoint معتمد. كذلك فإن تفاصيل DTOs واستجابات الخادم غير موثقة بالكامل في ملفات الواجهة السابقة؛ راجع أسماء الحقول مع الـBackend قبل التشغيل الفعلي.


## خادم Flask التجريبي (Mock API)

أضفنا مجلداً باسم `mock-backend` يحتوي على Flask API يحاكي المسارات التي تستعملها الواجهة في `src/lib/endpoints.js`. لا تحتاج إلى تغيير مسارات React. العنوان الافتراضي في `src/lib/api.js` أصبح `http://localhost:5000/api/v1`.

### تشغيل الخادم على Windows

افتح Terminal أولاً داخل مجلد `mock-backend` ونفّذ:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
py app.py
```

ثم افتح Terminal ثانياً في مجلد الواجهة (حيث يوجد `package.json`) ونفّذ:

```powershell
npm install
npm run dev
```

افتح عنوان Vite الذي يظهر في الطرفية، عادة `http://localhost:5173`. يجب تشغيل الواجهة والخادم باستخدام `localhost` معاً حتى تعمل جلسة Cookie المحلية بسلاسة.

## تحسينات واجهة المستخدم

- جميع قيم الحالات المعروفة في API تُعرض بالعربية من خلال `formatStatus`، مع إبقاء أي قيمة عربية كما هي، وتنسيق الحالات داخل شارات واضحة حسب نوع الحالة.
- نافذة إدخال العامل لتأكيد صرف الوقود ولوحة الإدارة لاعتماد/رفض طلب الشحن أصبحت نماذج Modal داخل الواجهة بدلاً من `window.prompt`.
- أُعيد تنظيم Sidebar إلى رأس وقائمة قابلة للتمرير ومنطقة حساب ثابتة في الأسفل لتجنب تداخل عناصر القائمة.
- أُضيفت حالات hover وfocus موحّدة للجداول والبطاقات والروابط والأزرار، مع تحسين تباعد الجداول والحقول.
- أُضيفت صورة `public/images/footer-station.png` كخلفية داكنة للـFooter.

## صفحات الموقع العامة والوثائق

- الصفحة الرئيسية متاحة عبر `/`، وأضيف رابط مباشر إليها في أعلى قائمة التنقل داخل Sidebar لجميع الأدوار.
- صفحة التواصل متاحة عبر `/contact`، وتتضمن بيانات اتصال توضيحية ونموذجاً محلياً يعرض رقم مرجعي تجريبياً. **النموذج لا يرسل الرسائل إلى Flask أو أي خدمة بريد**؛ يجب ربطه بمسار دعم حقيقي عند توفره.
- الشروط والأحكام متاحة عبر `/terms`، وسياسة الخصوصية عبر `/privacy`. توسعت الوثيقتان لتغطية الشحن اليدوي، الأرصدة والتخصيص، حجوزات عمليات الوقود، تسويات المحطات، الجلسات، الصلاحيات والاحتفاظ بالبيانات.
- الصفحتان القانونيتان ما زالتا مسودة للـMVP. بيانات الجهة المشغلة والاتصال والقانون الواجب التطبيق ومدد الاحتفاظ النهائية تحتاج اعتماداً ومراجعة قانونية قبل الإطلاق التجاري.
- معلومات التواصل في صفحة `/contact` مصطنعة ومخصصة للعرض، وينبغي استبدالها قبل النشر.
